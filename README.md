# deepsleep-whale

一只独立运行在 Mac 桌面上的鲸鱼娘。使用 rice-loving-whale 的动画和互动。

## 本地运行

首次安装、新电脑部署，以及各功能需要的前置服务、账号、凭据、权限和验收步骤，见 [安装与功能配置指南](docs/setup.md)。

需要 macOS、Node.js 22 或更新版本。

```sh
npm ci
npm start
```

安装依赖后也可以在 Finder 中双击 `start.command`。`.command` 是 macOS 可双击执行的 Shell 脚本后缀；文件使用英文命名，便于终端调用和工具引用。

启用 API 额度时，将项目根目录的 `.env.example` 复制为 `.env`，填写 `WHALE_QUOTA_BASE_URL`（Sub2API 站点地址）和 `WHALE_QUOTA_API_KEY`（管理 Key），并执行 `chmod 600 .env`。应用按项目目录读取该文件，终端和双击启动均生效，修改后须正常退出并重启。已有进程环境变量优先；未填写管理 Key 时兼容原有 `token` 文件。`.env` 已被 Git 忽略，勿提交真实凭据。完整步骤见 [安装与功能配置指南](docs/setup.md#地址与凭据)。

默认启动时同时显示控制小屋和透明桌宠。可在小屋首页右上角关闭“启动时显示小屋”，选择自动保存到本机 `settings.json`；下次启动或重启只显示桌宠，不创建小屋窗口，需要时可从托盘或桌宠右键菜单打开。直接拖动人物自由移动，不限制在屏幕工作区内；允许气泡暂时超出屏幕，提醒展开和节目切换也不会自动把人物拉回。点击人物随机触发害羞、开心、生气，默认三连击打开小屋。点饭碗喂饭，控制小屋的摸头按钮固定触发害羞。关闭小屋后桌宠继续运行，从菜单栏打开小屋或退出。

右键点击悬浮桌宠，弹出与小屋配色一致的自绘菜单，固定停靠在人物旁边，不随右键点位变化；主菜单与子菜单按实际尺寸避让屏幕边缘，展开时人物不移动。在“互动表情”子菜单中选择喂饭、摸头、开心、生气，在“小节目”子菜单中选择舞狮头、蓝鲸现世、可爱宅舞、轻快摇摆舞、抽陀螺、玩游戏气急败坏、撸猫、放烟花；也可打开小屋、收纳到边缘、隐藏桌宠或重启。支持方向键、Enter 和 Esc，也可点击菜单外关闭。喂饭、小节目播放期间和权限检查时，动作选项暂时不可用。菜单交互参考 [dsh-pet](https://github.com/PC2005-cloud/dsh-pet)。

桌宠挡住操作时，移到人物上点击右侧收纳按钮，或右键选择“收纳到边缘”：人物、气泡和额度条一起收起，只留下屏幕边缘的鲸尾书签。点击书签恢复到原人物位置；收纳时按人物当前位置选择最近的上下左右边缘；拖动书签并松手也会就近吸边，横向或纵向自动适配。人物未移动时，本次运行会记住书签位置；移动人物后重新选边。收纳期间新任务、日程提醒和未读消息只亮提示点，不自动展开，也不打开小屋。书签右键和托盘均可恢复或彻底隐藏；原屏幕断开时会移到可用屏幕。

收纳验证：`node --test test/pet-hit-window.test.cjs test/pet-hit-view.test.cjs test/pet-gesture.test.cjs`；`PLAYWRIGHT_MODULE=/path/to/playwright node scripts/checks/pet-storage-smoke.cjs` 检查真实点击、拖动、提示点与菜单；`node scripts/checks/pet-storage-smoke.cjs --preview` 启动使用临时数据、无外部服务的独立体验桌宠。

## 界面公共样式

小屋与桌宠弹窗共用 `src/ui/components.css`，统一按钮、输入框、下拉框、卡片、图标按钮及提示样式；颜色、字号、圆角和尺寸集中在 `src/ui/tokens.css`。榜单和账号选择窗额外引用 `src/ui/popup.css`，各页面只保留布局及业务专属样式。后续调整同类控件时优先修改公共层；紧凑窗口通过 CSS 变量调整尺寸。

新增单选菜单复用 `src/ui/select-view.mjs` 和由公共层引入的 `src/ui/select.css`，只提供选项、当前值和保存动作。快捷操作使用这一组件，包括展开项、选中态、禁用、键盘导航、焦点和关闭行为。原生 `<select>` 的系统展开菜单不能靠输入框 CSS 统一；需要统一展开外观时使用公共组件。样式验证须覆盖展开菜单、长标识、窄窗口及键盘操作。

微信账号改为平铺，复用 `components.css` 的 `ui-choice`、`ui-status`，设置窗口复用 `ui-dialog`；微信页面样式只保留布局与业务内容排列。

验证：`PLAYWRIGHT_MODULE=/path/to/playwright npm run test:styles`，使用静态页面夹具检查各窗口的计算样式、选中与焦点状态，以及小屋八个页面在 860 / 1060 像素宽度下的布局，不读取本机凭据或连接业务服务。

## 侧栏整理

除“陪伴小屋”外，其余 9 个模块的右上角均有总开关。关闭后，左侧入口和页面功能区一起置灰，仍可进入页面重新开启；后台暂停对应的接收、刷新和提醒，保留已有数据、账号配置及模块内的细项开关。开关独立保存到本机 `modules.json`，重启保留。微信关闭后断开接收和本机跟踪，已提交到客户端的对话不删除、不重跑；重新开启按原恢复规则继续跟踪。Archery 已发出的审核继续核实结果并保留防重记录，尚未提交的确认失效。

验证：`node --test test/module-settings.test.cjs test/module-runtime.test.cjs test/archery.test.cjs`；`PLAYWRIGHT_MODULE=/path/to/playwright npm run test:modules` 使用隔离服务与隐藏窗口检查开关、置灰、重启恢复及停用后的入口限制。

长按菜单约 450 毫秒或点击侧栏“整理”进入整理模式。虚线框右上角的 `−` 将菜单收进“显示更多”，更多里的 `+` 将其移回常用区末尾。拖动时相邻菜单平滑让位；两个区域各自支持排序，整理模式下也可聚焦菜单后按 Alt + 上下方向键调整。点击“完成”、侧栏外部或按 Esc 退出整理；拖动中按 Esc、失焦或取消手势会恢复本次拖动前的位置。

菜单顺序和收纳状态自动保存到本机 `sidebar.json`，重启保留；保存失败恢复上次有效布局并提示。收纳只改变入口位置，不停止对应功能，当前页面保持打开；“显示更多”始终保留，收纳了当前页时突出显示更多入口和数量。展开时箭头向下，菜单字号保持一致，通过缩进和细引导线显示层级。侧栏可独立滚动，展开更多不会遮挡底部入口。

验证：`node --test test/sidebar-settings.test.cjs`；`PLAYWRIGHT_MODULE=/path/to/playwright node scripts/checks/sidebar-smoke.cjs` 使用临时目录验证真实指针拖动、收纳/移回、防误触、键盘整理、保存失败回滚、重启恢复和小窗口布局。

## 快捷操作

小屋左栏打开 **快捷操作**，页面按“鼠标操作”和“任务提醒”分组。执行中、已完成、待处理共用提醒合并阈值（1–10，默认 3），各类分别计数：不超过阈值时逐条显示，超过时合并为“类别：数量”，点击可展开或收起。双击、三连击可分别设置为打开小屋、收纳到边缘、摸头、喂饭、开心、生气或不启用，例如“双击开小屋、三连击收纳”。默认双击不启用、三连击打开小屋；已有三连击配置保持不变。两种连击设置为同一有效动作时，两行使用相同的浅暖色背景，并在各自下拉框右侧提示与哪项配置相同，仍允许保存；改成不同动作或两者都不启用时，底色和提示一起清除。任一连击绑定“收纳到边缘”且快捷操作功能开启时，隐藏人物旁的收纳图标；取消收纳绑定或关闭快捷操作功能后恢复图标。修改后立即生效，配置单独保存在本机 `shortcuts.json`，重启后保留；保存失败时恢复上一次有效设置并提示。

鼠标左键相邻两次点击间隔不超过 400 毫秒时计为连击。同时启用双击和三连击时，第二次点击等待连击窗口结束后执行双击动作，第三次点击只执行三连击动作，不会先执行双击。只启用双击时，第二击即可执行；没有匹配的连击执行普通互动，两者都不启用时恢复即时普通点击。移动超过 5 像素按拖动处理；拖动、右键、失焦、取消及点击气泡或其他按钮会清除连击计数。小屋中的人物和键盘 Enter / 空格保持普通互动。

验证：`node --test test/shortcut-settings.test.cjs test/pet-gesture.test.cjs test/shortcuts-view.test.cjs`，覆盖两种手势独立保存、旧配置兼容、重启恢复、保存失败、连击互斥、单击回退、拖动及取消。

真实 Electron 检查：`PLAYWRIGHT_MODULE=/path/to/playwright node scripts/checks/shortcuts-smoke.cjs`，使用临时数据、关闭外部服务，先隐藏检查设置页，再验证真实双击打开小屋、三连击收纳、互不误触、禁用和重启恢复；需要现有 Playwright 安装。独立体验：`node scripts/checks/shortcuts-smoke.cjs --preview`，预设“双击开小屋、三连击收纳”，可在体验小屋继续修改。

## 日程备忘

小屋左栏打开 **日程备忘**，默认查看全部事项，按“定时提醒”和“待办事项”两个简洁分组展示。统一点击右上角“新建事项”，在同一弹窗中选择事项类型（待办事项／定时提醒）和所属分类（工作／个人），只展示对应的期限或计时设置；新建时切换类型保留已填名称、分类和各类型草稿，取消不保存。编辑已有事项可调整分类，类型保持固定。页面可筛选工作或个人，每条记录带分类标签；保存后切换到能看到该事项的筛选，避免记录被当前筛选隐藏。仅修改分类保留提醒进度、待办期限及完成状态。旧记录自动归为“工作”，两类共用默认时间及通知配置，可为单条提醒设置独立时段。筛选不暂停后台提醒。不自动添加或启用提醒；可用“添加喝水提醒”“添加闭眼休息”预填后保存，也可自定义。

循环提醒支持两种触发方式：**完成后计时**在本轮完成后重新计算间隔，**固定时间**按每天指定的时刻提醒。处理时长设为 0 时点击“完成”；大于 0 时点击“开始处理”，倒计时结束后自动完成。例如间隔 40 分钟、处理 3 分钟，10:02 提醒、10:06 开始处理，10:09 结束后才开始下一轮，下一次为 10:49。等待处理期间不重复提醒，固定时间遇到上一轮未处理也不积压；修改计时设置会重新安排下一轮。可暂停、恢复、编辑及删除。

默认提醒日为周一至周五、允许时段为 **10:00–19:00**。点击日程备忘页右上角的“默认配置”按钮，在弹窗中修改默认日期、时段、系统通知和提示音，保存后生效，取消或 Esc 放弃本次修改。日期提供“每天”快捷按钮，一键选中周一到周日，手动取消任一天后退出每天选中态。“全天允许”独立控制所选日期内不限时段，勾选后收起时间输入，摘要显示“每天 · 全天”或所选星期与“全天”。取消全天可恢复本次编辑的自定义时段，并可添加多个不重叠时段以避开午休；每条提醒也可取消“沿用默认提醒时间”单独设置。日期按星期选择，不自动识别法定节假日。全天模式跨连续允许日期保留待处理和处理倒计时，进入未选中的日期时停止；全周全天不中断计时。指定时段的开始边界包含、结束边界不包含，跨午夜的指定时段需拆开设置，至少一个指定时段须长于提醒间隔。修改默认工作时间会重新安排沿用默认值的提醒，不影响独立时段。

允许时段外不显示提醒气泡、不发送系统通知或提示音，未处理及未完成的处理倒计时在时段结束时收起，下个允许时段重新开始。间隔跨越下班或午休时不累计剩余时间，例如周五 18:50 完成、间隔 40 分钟，下次为周一 10:40。桌宠提醒气泡可直接完成或开始处理，也可打开本页；原有聊天提醒保留。系统通知和提示音在本页独立设置，开启后也用于提示处理倒计时结束；唤醒时下一轮已到期，则只提示新一轮。

待办可分别设置计划开始、结束日期，两者都可留空，之后也可编辑补填或清除；结束日期输入框旁的“快捷设置”保留“今天完成”“明天完成”“一周内完成”“指定日期”等安排，“不设结束日期”清空日期，表示结束未定。一周内为选择当天加 7 个日历日，选中后会填入具体日期，保存后日期固定，重启不会滚动延期。两端均填写时，结束日期不能早于开始日期。计划日期只用于排期，不自动改变处理状态；实际完成日期默认今天；编辑器选择“处理完成”后可填写过去的实际完成日期，补记历史任务无需逐步切换状态。已完成任务可从对应完成记录的“修改完成日期”入口更正，当前任务和原完成记录同时更新，不新增重复记录。一条待办按任务 ID 只展示一条最新完成记录，无论同一天还是跨天重新完成，都更新原记录；已有多条历史按最新写入记录展示并统计，读取不重写原始文件，更正日期后原日期不再展示旧副本。同名但不同 ID 的待办保持独立；原任务删除后最新完成记录继续保留。更正后工作待办移到实际完成当天的日报，保留人工整理的标题和说明。计划日期不会代替实际完成日期。待办分为“待处理、处理中、处理完成”，卡片按状态只提供下一步操作：待处理显示“开始处理”，处理中显示“处理完成”，已完成显示“重新处理”；编辑表单也可直接切换状态。支持备注和编辑，不使用勾选框表示完成；“今天”包含计划已开始或已到结束日期的未完成任务，“接下来”按计划开始日期（未设置时按结束日期）筛选未来任务，“未排期”仅包含两端都未设置的任务。默认“全部”和日期筛选只显示未完成任务，完成后立即移入完成历史并提供查看入口；“处理完成”筛选可单独管理已完成的原任务。旧记录沿用原截止日期作为计划结束日期，开始日期留空，原完成时间保留；重复完成不改写实际完成时间。待办排期不自动产生定时通知，也不受提醒时段限制。

日程备忘提供“事项安排”和“完成历史”两个入口。编辑或新建时直接保存为“处理完成”，会打开该任务完成日期的历史记录。首次完成时保存当时的标题、备注、分类、期限和完成时间；同一条待办再次完成时更新原完成记录，不新增历史。历史按最新实际完成日期及工作／个人筛选，可通过“修改完成日期”更正；日期变化时原日期不再显示旧副本。删除原任务后最新完成记录仍保留，重复点击完成不新增，也不重置实际完成时间。旧文件会为现存已完成任务补入历史，升级前已经删除的任务无法恢复。已完成的工作任务和工作类历史可点击“查看当日日报”，跳转到实际完成日期的每日工作；开启工作报告的日程同步后自动纳入，个人事项不纳入。重新处理会撤销当前日报来源的完成状态，完成历史仍保留。

工作安排、完成历史、提醒设置和运行进度保存在本机 `planner.json`，写入失败保留上次有效状态；文件损坏时保留原文件并停止写入。历史与任务原子保存，最多 20000 条且日程文件上限 32 MiB，达到上限拒绝本次写入并保留原记录，不自动删除历史。关闭小屋不停止计时；应用退出或电脑休眠时无法即时提示，启动和唤醒后仅补当前允许时段的一轮，不补发过期时段的提醒。已等待处理的提醒重启后恢复展示，不重放系统通知。完整工作备注与完成历史只开放给小屋，桌宠仅接收当前提醒摘要。

验证：`node --test test/planner.test.cjs test/sidebar-settings.test.cjs`；`PLAYWRIGHT_MODULE=/absolute/path/to/playwright npm run test:planner` 使用临时数据及可控时钟，拦截系统通知，检查真实 Electron 的循环提醒、处理倒计时、工作期限、保存失败恢复、权限隔离、重启和窄窗口布局。

## 消息订阅

订阅管理顶部为“我的订阅”，按名称、账号、自定义备注和操作分列。备注最多 200 字，可在列表直接修改并按回车保存，无需保存按钮，重启保留；“取消关注”停止自动检查并保留账号、备注及缓存，可点击“关注”恢复。标题栏右侧“添加订阅”打开弹窗，填写 X 账号或链接及选填备注，添加成功后关闭；取消或 Esc 关闭，失败保留输入。

小屋左栏在“陪伴小屋”下方打开 **消息订阅**，默认展示“订阅动态”；“订阅管理”集中添加账号、编辑备注、取消／恢复关注及清除缓存，“推荐关注”单独展示推荐账号。Tab 支持方向键和 Home/End 切换，重新进入默认回到动态。在“订阅管理”添加 X 用户名、主页或帖子链接（例如 `https://x.com/thsottiaux/status/2113162277688070445` 会识别为 `@thsottiaux`）。“推荐关注”按昵称、账号、推荐理由、是否关注分列，推荐理由支持直接编辑、回车保存，未填写时显示浅灰提示；理由独立保存，未关注、取消关注或清理缓存均不丢失，重启后恢复。提供 Tibo（`@thsottiaux`）的关注入口。点击“关注”加入订阅；“已关注”可点击取消关注，状态与管理列表同步，恢复关注不会重复添加账号。默认不自动订阅，最多订阅 20 个。首次读取和后续新获取的动态均默认为未读，显示侧栏未读数和卡片小绿点；点击消息左上角的账号时间标题可查看原文并设为已读，标题支持 Enter/空格操作；点击中文翻译也立即设为已读；在“只看未读”下，本次点击翻译的消息会保留供阅读，切换筛选、刷新或离开页面后再按未读条件过滤，避免译文返回前消息消失。“中文翻译”右侧的删除图标会直接删除该条原文、译文及未读记录，并中止该条翻译；本地每账号最多保留 1000 个删除 ID，更早的记录合并为删除截止线；刷新和重启不会恢复已删除的消息，截止线之前未缓存的旧帖也不再补回，已有旧缓存仍可保留和更新。删除订阅后重新添加会重置删除记录和截止线。正文默认展示两行，点击正文即设为已读；超过两行时同时展开，再次点击收起，Enter／空格也可切换，短文保持原样，不显示额外展开按钮。昵称采集后本地保存，消息、筛选项和管理列表优先展示昵称，悬停名字可查看账号；未获取昵称时回退显示账号。动态上方提供昵称/账号搜索框及横向筛选，实时过滤消息；也可只看未读或全部已读。取消关注保留内容和阅读进度；不发送系统通知。桌宠头部右上方显示奶白底、灰蓝描边的未读数字气泡，超过 99 条显示“99+”；未读数增加时短暂展开消息卡片，3 秒后收回数字气泡，普通状态刷新和启动恢复缓存不会重复展开；无未读或关闭消息订阅模块时隐藏。点击角标进入全部账号的未读动态列表，仅打开列表不会标为已读。

## 邮箱直接收件

小屋左栏打开 **邮箱接收**，填写邮箱地址、选择邮箱类型，再填写邮箱的客户端专用密码或授权码，点击“开始接收”。直接通过 IMAP 收件，不使用飞书开放平台应用、机器人或本机 lark-cli 登录。

“飞书邮箱”自动使用 `imap.feishu.cn:993`。先在飞书邮箱设置开启第三方客户端登录，并生成专用密码；企业管理员可能限制此功能。参见[飞书官方说明](https://www.feishu.cn/hc/zh-CN/articles/902478147400-在第三方邮箱客户端登录飞书邮箱)。其他邮箱选择“自定义 IMAP”，填写服务商提供的服务器地址和 SSL/TLS 端口。全部连接强制 TLS 并验证服务器证书，不支持明文 IMAP、POP3 或 OAuth 专用登录。

默认展示收件箱最近 20 封，可在邮箱配置中设置最近邮件数量（1–100 封），点击“保存并接收”保存生效；已有配置未设置数量时默认使用 20 封。后续每分钟检查一次，也可“立即收取”。发现新邮件时发送系统通知，开关沿用小屋设置。两次收取间新增超过所设数量可能无法完整提醒，请在原邮箱查看完整邮件。暂停后停止同步，保留本地邮件供查看；重启先显示本地缓存，再恢复已启用的连接和去重记录。网络失败时保留上次缓存。更换邮箱或服务器需要重新填写专用密码，连接失败时保持原连接暂停；相同配置可留空沿用已保存的密码。收件箱 UIDVALIDITY 改变时重新建立基线，不重复提醒历史邮件。

选中邮件后，邮件列表行右侧显示删除图标。确认后从小屋移除该邮件及本地正文，原邮箱中的邮件保留；删除记录加密保存，刷新和重启不重新显示。更换账号、服务器或收件箱 UIDVALIDITY 时重新建立删除范围，避免误隐藏其他收件箱的同编号邮件。

可在小屋 **Archery → Archery MCP 配置** 选择 Codex 全局 `config.toml` 并“保存并连接”。连接成功后显示“已连接”并收起配置；修改路径后可重新保存，连接失败时可“重新连接”。桌宠直接调用已有 Archery MCP，由 MCP 自行加载账号配置（包括独立安装环境的 `.env`），无需重复填写密码。仅保存路径，不改写全局配置；“在文件夹中显示”定位所选文件，不启动默认编辑器。

密码、连接配置、最近邮件列表和纯文本正文，以及最近 1000 个去重邮件 ID，使用 Electron 系统安全存储加密保存在本机 `mail.enc`，系统加密不可用时不降级明文。输入密码提交后清空，不回显到界面快照。密码框的眼睛按钮可显隐新输入的密码，也可主动查看当前相同邮箱及服务器已保存的密码；隐藏、收起配置或离开邮箱页时清除仅供展示的已保存密码。之前误做的开放平台 `mail.json` 不再使用，文件保留，不自动登录原应用。

收件箱以只读方式打开；同步时自动按 UID 下载并解析最近邮件（单封原文上限 5 MB，包含附件），缓存纯文本正文与附件名称；已缓存正文直接从本机读取，不重复下载。单封下载失败会在后续同步时重试，也可点击重试。缓存随设置的数量裁剪，更换邮箱、服务器或收件箱 UIDVALIDITY 后隔离旧缓存。原始 MIME 与附件文件不落盘，不打开附件或远程图片、不修改已读状态、不发送回执。邮件不交给 AI，也不作为本机任务执行。邮件内容不进入桌宠广播或系统通知。

验证：`node --test test/imap-mail.test.cjs test/imap-wire.test.cjs test/mail-view.test.cjs`；界面验证：`PLAYWRIGHT_MODULE=/absolute/path/to/playwright npm run test:mail`。使用隔离的模拟 IMAP、真实 TLS 协议会话和测试数据，不访问真实邮箱；实际收件仍需在本机填写自己的邮箱配置后验证。

Archery 当前固定随主程序提供，无需下载安装插件。插件方案暂缓接入；原型源码及接入差异留存在相邻 `../deepsleep-plugins/host-prototype`，独立 Archery 插件项目也保留，正式应用不加载插件宿主或显示插件管理菜单。原连接配置与缓存路径不变；试用期间的 Archery 菜单位置会归回内置入口，缺少正式模块开关时接续试用状态，已有模块设置优先。

标题右侧是自动刷新开关，显示“已连接”或“已暂停”。已连接时桌宠启动立即读取待当前账号审核的数据工单，之后每 5 分钟刷新当前来源页；关闭小屋或切到其他页面仍继续。已暂停后停止定时读取，已有列表保留，仍可立即刷新。开关保存在本机 `archery.json`，重启后保留；保存失败时保持原状态。可以立即刷新、上一页、下一页，每页最多读取 20 条混合来源记录；类型筛选后本页可能为空但仍有下一页，页面不会将来源总数说成数据工单总数。没有后台自动翻页。点击整条工单摘要在下方展开 SQL 和执行结果，再次点击收起，切换工单只展开当前一条；点击“审核通过”后，应用内确认框逐笔展示编号、标题和目标。默认聚焦取消，直接按 Enter、Esc、切页或关闭窗口都会取消；明确确认只审批这一笔，不请求执行 SQL。

此功能独立连接 MCP，不经过模型，固定读取 `work_order_pending_list`，仅在逐笔确认后调用 `work_order_approve`（一个编号，备注“审核通过”），遵守全局工具启停限制。待审核行并列展示紧凑的“审核通过 / 审核拒绝”，窄窗口下放到摘要下方；拒绝时必须填写原因，确认后只对当前编号调用 `work_order_terminate`，成功后移出待处理列表，需独立开放该工具权限。审批与刷新互斥，列表超过 5 分钟未成功刷新时需先刷新。审批失败不自动重试；通过与拒绝共用防重，结果未知时保留提示，本次运行禁止再次通过、拒绝或执行该编号，请到原工单核实。凭据只在主进程读取，不传给界面、不复制落盘。仅摘要在内存保留，重启后重新获取；同账号读取失败保留最后成功列表与时间，后续定时重试。全局账号或连接参数变化后丢弃旧会话和摘要；退出停止轮询并关闭子进程。

验证：`node --test test/archery.test.cjs test/archery-view.test.cjs`；界面冒烟：`PLAYWRIGHT_MODULE=/absolute/path/to/playwright npm run test:archery`。自动化测试使用合成配置和本地 MCP 协议替身，不调用真实工单接口。

## API 额度

小屋左栏打开 **API额度**，查看账号的订阅类型、5 小时和 7 天剩余百分比、点数余额及可用重置卡张数。点数位于账号名称下方，可通过列设置单独显示或隐藏，来自网关已保存的 `extra.codex_credits_snapshot.credits.balance`，随账号额度一同刷新、缓存；支持小数并以千分位展示，余额为 0 显示“0”，缺失或无效时显示“—”。只有点数、没有百分比额度的账号也会展示。“平台/类型”列分组显示 OpenAI / OAuth、Pro 100 或 Pro 200 / 重置次数，并显示订阅到期日期。重置次数代表可用重置卡张数。订阅按平台字段将 `prolite` / `pro` 显示为 Pro 100 / Pro 200；缺失时显示“订阅未知”。重置卡无数据时显示“—”，不会当作 0 张。账号额度标题栏的“刷新频率”统一输入秒数，固定“秒”后缀，默认 300 秒；秒数与紧凑换算（如 2分、1时1分5秒）置于同一个随内容伸缩的外框，达到 60 秒时在内部以“秒 / 换算时长”显示，不足 60 秒隐藏换算并收窄；外部占位固定，标签和按钮不移位；超长换算省略显示，悬停查看完整内容，悬停提示有效范围 5–86400 秒。输入过程中不保存，按 Enter 或离开输入框时自动保存；小于下限自动补到 5，大于上限自动降到 86400，清空后完成编辑恢复原值。刷新过程中也可修改频率并立即保存，当前请求不被打断，结束后按最后保存的频率重新计时。保存成功不额外显示提示，失败时保留输入和原频率，并提供就地重试。旧分钟/小时配置自动换算显示，修改后按秒保存，重启保留。打开时先检查上次同步时间，未到设定间隔沿用已有数据，到期或没有历史记录时读取；近期失败也按该间隔等待重试。每次请求完成后再等待设定间隔，避免请求重叠，切换页面或关闭小屋仍继续；点击“立即刷新”可手动更新并重新计时。刷新期间按钮禁用，重复请求合并。

每个账号有“参与刷新”开关，默认开启，与自动刷新间隔一起保存在本机 `quota-refresh.json`，重启后保留。每轮手动及自动刷新先分页获取完整账号列表，只更新开启刷新的账号，并发现新增账号；开启刷新但未出现在完整列表中的已知账号，再通过 `GET /api/v1/admin/accounts/:id` 单独补取。列表读取失败不触发逐账号补取，补取失败保留该账号旧值，其他成功账号照常更新。关闭的账号保留已有数据，全部关闭则暂停轮询。返回账号摘要包含 `lastSyncedAt`（本机最后成功同步网关数据的毫秒时间戳），在“剩余用量”后的独立“刷新时间”列分两行显示年月日（YYYY-MM-DD）和时分秒（HH:mm:ss），支持单独显示或隐藏，并写入缓存；暂停或失败不推进时间，旧缓存缺失时显示“尚无同步时间”。该时间不代表网关查询上游额度的时间。单账号手动刷新仅更新对应账号及其同步时间。设置保存失败保留原值，刷新期间暂时不能修改开关。

请求超过 60 秒中止；单个账号失败保留该账号原值并继续读取其他账号，整轮全部成功才更新成功时间、清除失败标签。失败显示红色“同步更新失败（失败时间）”标签，按已保存的刷新间隔重试。连续失败始终保留第一次失败的时间，同步成功后清除；恢复后再次失败时重新记录起始时间。重试间隔独立计算，不受标签时间影响。额度摘要、成功时间、首次失败时间和下次刷新时间原子保存在本机 `quota-cache.json`。缓存只含界面摘要，不保存凭据，按接口地址和 token 摘要隔离。重启后先显示缓存，首次打开页面才恢复剩余刷新时间；过期时刷新，失败保留已有数据。文件损坏时重新同步，保存失败单独提示并保留旧文件。退出后停止轮询。验证：`node --test test/quota-accounts.test.cjs test/quota-cache.test.cjs test/quota-view.test.cjs`；真实窗口检查：`PLAYWRIGHT_MODULE=/path/to/playwright node scripts/checks/quota-smoke.cjs`。使用合成数据，不访问真实账号接口。仅检查点数显示、刷新和缓存恢复：在窗口检查命令前增加 `WHALE_QUOTA_CREDITS_ONLY=1`。仅检查自定义周期：在上述窗口检查命令前增加 `WHALE_QUOTA_INTERVAL_ONLY=1`。

用户排行上方新增独立的 **Key 今日消费** 查询列表。展开账号选择器后加载最多 30 个 Sub2API 用户，支持搜索邮箱或用户名；这里选择的是登录用户，不是上游订阅账号。选中后分页读取该用户全部现有 Key（每页 100，最多 1000；超限或分页不完整会报错），再通过 `POST /api/v1/admin/dashboard/api-keys-usage` 一次批量查询各 Key 的 `today_actual_cost`，展示每个 Key 的今日实际扣费、状态、分组小计和账号合计。整个 Key 今日消费区块支持折叠并保存偏好，重启后恢复；收起后保留标题和消费汇总，并暂停定时检查，展开后检查到期缓存。各分组支持独立折叠，收起后保留 Key 数和消费小计；折叠不请求接口，当前窗口内按账号保留折叠状态。按 Key 当前所属分组归类，同一 Key 当天换组前后的扣费合并；今日扣费口径沿用 Sub2API 服务端时区。该批量接口不提供 Token 或生图专属统计，因此此列表展示所有调用的今日扣费。查询与消费榜的分组、每日／每周筛选独立。账号搜索有 300ms 防抖和 30 分钟内存缓存；选中账号及最近 10 份用户／日期结果保存在本机 `quota-key-usage.json`，仅缓存界面摘要，完整 Key 和管理凭据不下发页面或写入缓存。重新选择、切页、重启复用 30 分钟内的结果；页面可见时到期更新，可手动刷新。失败保留该账号当天的旧结果，跨日立即清空昨天数据。验证：`node --test test/quota-key-usage.test.cjs`；窗口交互和布局：`PLAYWRIGHT_MODULE=/path/to/playwright node scripts/checks/quota-keys-smoke.cjs`，使用合成数据，不访问线上。

“用户排行”位于账号额度下方，支持点击标题折叠或展开，折叠状态重启后保留；默认分组 13，分组名称来自源项目的 `GET /api/v1/admin/groups/all`，可搜索切换或选择“全部分组”。支持“每日”（上海时间当天）和“每周”（上海时间本周一至今天），通过 `GET /api/v1/admin/dashboard/user-breakdown` 展示最多 20 位用户的请求数、输入／输出／缓存／总 Token 和实际费用，按实际费用降序排列。Token 使用 K/M 缩写，费用保留 4 位小数，悬停可看原始值。排行每 30 分钟刷新，也可点“立即刷新”；标题右侧仅显示上次成功刷新时间，不显示已同步标签和下次刷新时间。关闭账号刷新开关不影响排行。按分组、排行策略和日期保存在本机 `quota-group-usage.json`，保留最近 20 份摘要及所选分组和策略，兼容迁移旧版每日缓存。重启先显示缓存，满 30 分钟再更新；旧缓存缺少分组名称时独立补查名称目录，不重复拉取仍有效的排行。分组、排行策略使用相同的下拉菜单样式，标签与选项横向对齐，不展示额外日期说明。切换分组、策略、跨日和凭据变化时不混用缓存。连续失败保留数据和首次失败时间，成功后清除红色提示。测试：`node --test test/quota-group-usage.test.cjs`，窗口交互检查同上。分组接口参考：`https://github.com/Wei-Shaw/sub2api/blob/main/frontend/src/api/admin/groups.ts`。

账号额度下方的“流量跟踪配置”可单选跟踪账号、设置淡黄色和淡红色阈值（默认低于 30% / 10%）。底部胶囊条按该账号的 7d 剩余百分比填充，保留任务状态文案；悬停显示账号、百分比、重置时间及暂停／失败状态。双击底条中间区域弹出账号列表，展示账号名称、7d 剩余额度和暂停状态，当前账号带选中标记；点击账号后立即切换并保存，按 Esc 或点击外部取消；左右按钮保留各自功能。主配置固定名为“流量跟踪配置”，标题右侧的复制图标可在下方新增“流量跟踪配置-2”“流量跟踪配置-3”等；副配置标题右侧也可复制或删除；最多保留 3 条副配置（含主配置共 4 条），达到上限后禁用所有复制按钮，删除后可继续复制，新增优先补齐最小空缺编号（例如删除 2 后再新增仍为 2），已有配置不改号，界面按编号排列。每份配置可分别选择账号、设置颜色阈值、折叠并保存。复制出的副配置默认暂不跟踪；副账号不能与主账号或其他副配置重复，保存的账号与桌宠临时选择均参与互斥。主配置不受限制，切换账号时会把冲突副配置改为暂不跟踪，保留其阈值与榜单分组。旧版重复选择保留主配置及最先出现的副配置，其余改为暂不跟踪。主配置的今日消费榜跟随下方用户排行，副配置可独立选择分组或全部分组。每条额度条都有左侧榜单入口和右侧刷新按钮；副条中间展示账号和百分比。桌宠上双击主条切换会同步主配置，副条切换仅临时生效，重启恢复各副配置中保存的账号。删除副配置同时移除对应额度条；副条较多时可滚动查看。兼容旧版多账号开关及双配置数据。专项界面验证：`WHALE_QUOTA_MULTI_ONLY=1 PLAYWRIGHT_MODULE=/path/to/playwright node scripts/checks/quota-smoke.cjs`。左侧榜单入口在对应账号条旁展开当前查询分组的今日消费前五名，底边随被点击的账号条对齐，靠近屏幕边缘时自动避让；榜单标明来源配置与当前跟踪账号（包含副条临时选择），不足五人按实际人数展示；小屋选择每周时也不会把周数据混入今日榜。底条右侧原屋子位置改为账号额度刷新按钮，只读取该条当前跟踪账号的详情，其他账号的按钮和自动刷新时间不受影响；今日榜标题右侧可直接选择分组或全部分组，主配置与小屋分组同步并保留每日／每周策略，副配置仅修改自身的榜单分组；右上角的刷新按钮只更新当前分组的今日排行，可跳过半小时缓存，刷新期间禁用重复点击。榜单可按 Esc 或点击窗口外关闭。两处共用本地缓存，失败保留上次数据，跨日或切组不沿用其他范围的数据。账号额度、流量跟踪配置可分别折叠，状态、账号和阈值保存在本机 `pet-quota-settings.json`，重启后恢复。桌宠启动后即检查缓存新鲜度，账号额度按自定义间隔（默认 5 分钟）、今日排行按 30 分钟更新，折叠不暂停刷新。未选择账号或账号无有效 7d 数据时，底条保持中性底色。

## 微信远程排查

小屋左栏打开 **微信接入**，直接点击“扫码连接”，用微信扫描并确认，无需先绑定项目或填写客户端路径。默认使用本机 Codex 的可执行文件、配置和登录；deepsleep 不配置模型 API Key，也不修改客户端的 provider、代理或认证文件。

连接后，在微信中选择工作内容：

1. `/projects` 列出最近 Codex 对话中的项目，显示项目名称和目录，回复数字（如 `1`）选择；没有历史的新项目可用 `/project 本机绝对路径`（支持路径中的空格）。列表有下一页时回复“下一页”，也可使用 `/projects next`。
2. 直接发送问题，在所选项目创建新对话；继续发送文字会续接同一对话。`/new` 为下一条文字创建新对话，也可 `/new 项目编号或绝对路径`。
3. `/chats` 用汇总表列出所选实例的本机 Codex 对话，默认每页 5 条，显示编号、对话标题、项目名称及客户端，回复数字选择后直接追问；自动模式尚未选定实例时汇总所有启用的 Codex，未展示项保留到下一页。有后续条目时，表格底部显示 `0｜下一页｜当前每页 N 条`：回复 `0` 翻页，`0 10` 从下一页起每页显示 10 条；支持 1–20 条。`/chats 10` 从首页按 10 条显示，重新发送 `/chats` 恢复默认 5 条；也可用“下一页 10”或 `/chats next 10`。最后一页隐藏翻页行，长表格按完整行分段并重复表头，整页编号连续。长标题适当截短，项目仅显示目录名，不转发历史正文或首条提示预览。引用整张表格不能指定某一行，请使用编号选择。
4. `/status` 查看当前实例、项目、对话和任务，`/stop` 停止自己的任务，`/retry` 仅重试待投递结果。

数字回复只选择当前联系人最近列出的项目、对话或客户端，选择完成后数字恢复为普通任务文字。原有 `/project 编号`、`/chat 编号`、`/client 编号` 仍可使用。指令兼容复制时混入的零宽字符、全角斜杠和句末标点；路径、审批编号与任务正文保持原样。未知指令仅提示下一步，完整命令表通过 `/help` 查看。

**多个 Codex / 客户端：** 打开“微信设置”的“客户端”分类会自动检测 macOS 上已打开的 Codex / Cursor 桌面客户端，可点击“添加到优先级”，再用“上移/下移”排序并保存；刷新不会覆盖尚未保存的配置，同一实例显示“已添加”。Codex 根据运行中的后端及其打开的状态库/IPC 路径确定可执行文件和配置目录，只读路径、不读取进程参数、认证或聊天正文；不能明确对应的实例提示自定义添加，不默认套用另一个账号。Cursor 通过已登录的 CLI 接入，不复用编辑器已有对话。自动检测不枚举独立终端 CLI 的 profile；此类情况或未启动的客户端可用“自定义添加”，高级选项填写已有路径、Codex 配置目录或 profile。不同配置目录对应不同本地会话库；已有桌面对话继承原设置，新建 CLI 对话使用所选目录的默认配置或自定义 profile。优先级用于新对话的默认实例，已有对话固定所属实例，失败不会跨账号重跑。微信里用 `/clients` 查看顺序，`/client 编号` 指定实例，`/client auto` 恢复优先级选择。所有实例停用时仍可连接微信，但不能执行任务。旧版加密绑定自动迁移并保留原有会话。

**小屋最近任务：** 按实际对话汇总最近保留的 50 条任务，对话名称后同行显示项目、客户端和任务数量，右侧显示最近状态。点击会话标题后，在原列表下直接显示聊天气泡：提问在右、对应回复在左；提问侧使用已保存的头像，名称优先显示联系人备注，其次为当前微信的备注名、昵称；回复侧显示客户端名称和应用图标。按任务时间从早到晚排列，无需逐条点击查看内容。每页 10 组完整问答，上一页查看更早记录、下一页查看更晚记录，问答不会跨页拆开。每组问答默认无边框、透明背景；中断或取消显示淡黄色，执行失败或投递失败显示淡红色；只读取当前页正文，后台刷新保留当前页及阅读位置。进行中的任务显示等待回复，结束后更新对应回复；读取失败可单独重试，旧版已清理的正文无法补回。每组顶部保留时间，状态文字仅在中断、取消或异常时显示。点击选中一组已结束问答后，右上角才显示垃圾桶图标，点击仅删除这一组；支持 Enter/空格选中、Esc 取消。会话标题旁可删除整组已结束记录，同时停止相关任务的后续投递；不删除客户端原对话，不撤回已发送或发送中的微信消息，也不重新执行任务。其他对话的状态更新不会切走当前明细。不同客户端或身份配置的记录分别归组；Codex 名称从对应配置目录的本机会话库只读获取，读取不到时使用已选择的对话名称或短标识，不以微信联系人 ID 代替。

**微信用户信息：** 扫码账号本人发送 `/settings`，回复 `1` 进入用户信息，再回复 `1` 修改昵称、`2` 修改备注名、`3` 修改头像。昵称和备注名使用 40 字以内的单行文字；已有头像时，菜单新增 `4 查看头像`，返回当前头像缩略图后可直接发送新图片替换，或发送“清空”移除头像，无需再回复 `3`；也可继续用编号修改昵称或备注名。`3` 修改头像入口保留。清空头像后隐藏查看入口。选择头像后，单独发送一张 PNG/JPEG 图片（最大 4 MB），会居中裁切并缩成 128×128 的本地头像。编辑时发送“清空”恢复默认，回复 `0`、取消或退出可结束设置；五分钟未完成会超时。其他控制指令也会退出设置。任务执行、排队或等待回答时，需先结束任务再修改资料。设置只开放用户信息，每个微信分别加密保存；电脑账号卡片优先显示备注名，没有备注名显示昵称，同时显示头像。在电脑“微信接入”页点击账号头像（未设置时点击占位头像）可预览，并通过“更新头像”选择 PNG/JPEG 图片，使用相同的大小限制和裁切规则，保存后同步账号卡片和对话头像。这些资料用于 deepsleep 内的账号展示。

微信页面顶部按账号卡片展示连接状态、任务数、待授权及待投递数量，点击账号查看对应任务；切换不影响其他微信的连接。所选账号卡片内显示接收消息开关和删除操作；状态位于名称旁，连接中、重连中以灰色短线依次明暗变化的加载图标表示，连接成功后显示静态绿点。登录失效时突出“重新登录”，删除已绑定账号须确认名称与影响。新增但未扫码的微信可直接删除，取消或二维码展示期间均可移除。点击账号卡片中的备注名或昵称值弹窗编辑；内容变化后显示“应用”，Esc 或点击弹窗外可取消。客户端、联系人授权和完整使用方法放入“微信设置”窗口，支持 Esc 关闭与键盘切换分类。首次连接成功后，任务空白区提示发送 `/projects` 或 `/chats`。昵称及备注名限 40 字以内，随连接文件加密保存，分别按微信隔离，不改变账号身份、授权或会话；技术 ID 可在详情中查看。

客户端身份配置改变会清除相应的微信续接 ID，避免用新账号/目录误续旧对话；改优先级或名称保留既有对话。任务运行或排队时禁止修改客户端和切换发起人的选择。每个任务冻结实例、目录和会话，全局串行，最多 5 个待处理任务，单任务最多十分钟。不会在执行失败后自动切换实例、重跑模型任务。由终端环境提供的代理变量仍需在启动 deepsleep 时可用；从 Finder 启动不保证继承终端环境。

**继续桌面对话：** `/chats` 选择后，微信文字原样通过本机私有 IPC 交给持有该会话的 Codex 桌面进程，沿用该会话的上下文、模型、provider 和权限。桌面正在回复时先等待，空闲后仅投递一次；完成后只回传本轮最终助手回复，不回传旧历史、工具输出或思考内容。不会另起 app-server 恢复或抢占该桌面对话。Codex 桌面端须保持运行并持有选中的聊天；无 owner 时请先在桌面打开该聊天。多实例按配置目录连接对应的 `ipc/ipc.sock`；可执行路径/profile 仍用于列表查询与 CLI 新会话，不覆盖桌面对话设置。此接口属于内部协议，版本不匹配时明确失败，不自动改走 CLI。

桌面转发在提交前加密保存消息标识，取得轮次 ID 后立即保存。`/stop` 在投递前只取消等待，投递后只中断已确认的本轮，不停止桌面先前的任务。短暂断线或开始回执丢失后，在最多 30 秒内重连并只跟踪原轮次，不重新提交任务；原轮次已完成则补发最终回复，仍运行则继续等待，中断或无法确认则明确通知微信。仅将本轮可审查的命令/文件审批转发微信，通过 `/allow 编号` 或 `/deny 编号` 回复；断线前的审批编号失效，恢复后重新核对仍存在的原请求，桌面已处理的审批不会重复提交。

**处理状态：** 普通任务和问答答案不再发送“收到”“已收到答案”等额外回执，处理时使用微信原生“正在输入…”状态，每两秒刷新。等待回答/审批时暂停，继续处理后恢复；完成、失败、取消、暂停连接或撤销授权时停止。输入状态接口不可用不影响任务与结果投递；只在内存按账号和联系人缓存十分钟票据，停止时也会刷新过期票据。问答、审批、异常和主动查询仍发送文字；消息排队时每位联系人只在首次进入等待队列时收到一条提示。

**需要用户回答时：** 微信任务运行期间，Codex 的选项/填空问题会逐题发到微信，分开显示问题、选项和回复方式。有选项时可直接回复数字（例如 `1`），也可用自己的话说明选择、要求或疑问；填空题直接回复文字，包括以 `/` 开头的项目绝对路径。正常作答无需复制问题或填写问题编号，多道题答完后交回原请求，继续同一任务。`/question` 重看当前问题，并显示 `/answer 问题编号 答案` 的备用作答方式。等待回答时数字优先作为答案，不用于切换对话；已知指令（如 `/stop`、`/status`）仍按指令处理，其他联系人不能代答。桌面已回答或撤销的问题、已经结束的轮次不再接收微信答案；五分钟未答会请求停止本次任务，重启不重发失效提问。支持公共 app-server 的阻塞式问题及执行中的异步问题；桌面对话使用内部 IPC，版本兼容性仍需实际验收，异步问题在原轮次结束后不再补交。普通文字问题随最终回复回传，直接发送答案即可继续同一会话。命令/文件审批仍使用 `/allow 编号` 或 `/deny 编号`，两分钟未处理则拒绝。

**新建 CLI 对话：** `/project` 后直接发送文字或使用 `/new`，保留公共 app-server 创建会话的行为，其后续追问固定走 CLI，不冒充桌面对话转发。每轮显式使用工作区写入沙箱，写入根目录限定为所选项目，禁止默认网络访问及额外临时目录写入；额外权限的可审查请求通过微信逐次确认。两分钟后默认拒绝，不同意整会话授权、缺失审查内容的请求或持久权限规则。新 CLI 会话在桌面中的展示仍需实际客户端验收。

失败回复、小屋最近任务和 `/status` 会显示失败阶段、受控原因及可用的 RPC 错误码。原始服务错误和 stderr 可能含凭据，不直接转发或保存到诊断；未知异常明确标为原因未知。任务失败不会自动重跑，旧版已丢弃的错误无法事后恢复。

Cursor 需要可用且已登录的 **Cursor CLI**，使用 Ask 模式，只读排查；可以在微信选择绝对项目路径后创建与续接桥接会话。Cursor 编辑器已有聊天不在 Codex 会话列表中，不宣称编辑器和 CLI 会话互通。

支持最多 8 个微信连接、多个客户端配置、按微信及联系人隔离的项目/对话选择和私聊文字。在“微信接入”点击“添加微信”，用另一个号单独扫码，原连接继续保留；点击账号卡片只切换当前管理的连接，不暂停其他微信。正常连接不展示扫码入口；未绑定时显示“扫码连接”，登录失效时显示“重新登录”，临时断线会自动重连，也可点击“重试连接”复用原凭据。主动重新扫码登录放在“微信设置 → 账号操作”内，确认影响后使用原微信扫码；更换微信请通过“添加微信”接入。新增连接复制当前已保存的客户端配置，此后分别管理；联系人、会话、任务、问答、审批和投递各自隔离，任务在所有连接间统一串行排队。已有单账号数据自动迁移，重复扫码已接入的账号不会覆盖旧连接。扫码账号自动授权，其他联系人先发送消息，再在电脑上授权；授权前的消息不会补跑。图片仅用于头像设置，暂不支持群聊、语音或任务附件。电脑与 deepsleep 需保持运行、联网；睡眠期间无法处理新消息。微信任务状态显示在接入页，原有 Hooks 动画与提醒继续由各客户端事件驱动。

微信连接通过 iLink 扫码和长轮询实现，参考固定版本的 Hermes 微信适配器，无需安装 Hermes / Python。源码调查、协议依据与验证范围见 [微信接入调查](docs/wechat-source-research.md)。接口或客户端版本变化可能需要适配，真实扫码与模型/provider 的可用性仍需在客户环境验证。

启用此功能后，微信指令会交给所选本机客户端，任务回复及审批内容经微信发送；客户端按自己的配置访问模型和工具。微信凭据、联系人、会话 ID、去重游标、待执行/投递内容和最近 50 条任务的提问及最终回复，通过 Electron 系统安全存储加密保存在数据目录的 `wechat.enc`。正文不进入持续广播的页面快照或日志，仅在小屋主动查看对应任务时读取；记录超出上限或删除、解绑时清理，系统无法加密时拒绝保存。客户端自身的历史、日志和认证仍由客户端管理。“暂停接收”只停止所选微信的连接与当前任务；“解绑”只清除所选微信的本机状态与待投递内容，其他微信继续连接，最后一个微信解绑后仍保留客户端配置，不宣称撤销微信服务端凭据。正常退出仅断开桌面结果监听，保留原轮次；重启后显示“恢复跟踪中”，按已保存标识恢复结果跟踪。没有可靠关联的旧任务、尚未执行的排队任务和本地 CLI 任务会标记中断并通知微信，不自动重跑；结果发送失败仅重试投递，沿用原消息 ID。恢复依赖桌面仍提供原轮次；历史已被清理时不会猜测其他轮次的结果。

## 目录与职责

| 目录 / 入口 | 职责 |
|---|---|
| `start.command` / `src/main.cjs` | macOS 启动脚本 / Electron 装配入口 |
| `src/app/` | 协调应用生命周期、窗口菜单、Hooks 接收偏好和事件处理 |
| `src/domain/` | 任务聚合、工具权限状态、动画与互动规则；不依赖 Electron 和脚本 |
| `src/hooks/` | 客户端事件适配、配置生成与检测、Cursor 配置事务、本地事件桥及发送端 |
| `src/clients/` | 客户端进程检测、Codex 审批状态观察、只读聊天元数据和原对话跳转 |
| `src/channels/` / `src/agents/` | 微信、邮箱、Archery 接入及加密状态 / 独立的本机 Codex、Cursor 执行适配 |
| `src/ui/` | 页面、样式、受限 preload；提醒与 Hooks 页面各自使用独立渲染模块 |
| `src/shared/` | 统一事件协议与小节目清单 |
| `scripts/hooks/` | 配置预览、安装等命令行工具 |
| `scripts/checks/` | 递归语法检查和 Electron 专项验证 |
| `scripts/assets/` / `scripts/cursor/` | 动画资产处理 / 本地辅助扩展打包 |
| `test/` / `vendor/` | 单元测试 / 保留上游许可的养成模块 |

主进程由 `app` 协调 `domain`、`hooks` 和 `clients`；页面通过 preload 获取快照和提交操作，不直接访问文件或客户端存储。运行时配置生成在 `src/hooks/config.cjs`，不反向依赖 `scripts`。

项目仅保留 `deepsleep-whale` 目录，不依赖旧目录链接。Hook 配置使用当前项目绝对路径；从旧目录迁移后，需要同步更新 Codex / Cursor 的命令路径，并在 Codex 中重新审核、信任变更后的定义。

`scripts/codex-hook.cjs`、`scripts/cursor-hook.cjs` 是保留的稳定兼容入口，内部实现位于 `src/hooks/`。已安装的绝对路径和生成的 Hook 命令保持一致，目录拆分无需重装或重新信任未变化的定义。关键中文注释说明状态优先级、暂时隐藏、去重、跳转确认和配置回滚等边界。

## Codex 本地事件接入

应用通过当前用户可访问的 Unix socket 接收事件，不开放网络端口。发送脚本只传事件类型、会话 ID、轮次 ID，以及可选的工具调用 ID / 工具名称；丢弃提示词、工具输入和聊天正文。桌宠不在线时脚本在 800ms 内退出，输出中性 `{}`，不批准或拒绝任何操作。

### 1. 安装提醒配置（首次使用）

在本项目目录执行：

```sh
node scripts/hooks/install.cjs
node scripts/hooks/install.cjs --install
```

第一条预览合并结果，第二条安装。默认写入 `~/.codex/hooks.json`；如果设置了 `CODEX_HOME`，则写入该目录下的 `hooks.json`，须与 Codex 实际使用的目录一致。安装会保留已有配置，覆盖前创建带时间戳的备份，不会修改信任设置。若已安装本项目的 Hooks，无须重复安装。

如需手动配置，运行 `npm run hooks:config --silent`，将输出合并到同一配置文件，保留其他 Hooks。

### 2. 在 Codex 中查看并信任

- **桌面版**：打开 Codex 设置中的 **Hooks** 页面，找到命令路径指向本项目 `scripts/codex-hook.cjs` 的条目，查看并信任这些提醒 Hooks。入口名称以安装版本为准。
- **命令行版**：启动交互式 Codex 后输入 `/hooks`，查看并信任上述条目。`/hooks` 不是普通终端的 shell 命令。

“信任”允许 Codex 在对应事件发生时运行提醒脚本，不会授权桌宠替你批准其他操作。新建或变更的 Hook 定义需要重新审核。桌面版的审核入口见 [官方更新说明](https://learn.chatgpt.com/docs/changelog)，信任机制见 [Hooks 文档](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)。

### 3. 验证真实联动

1. 保持桌宠运行，打开控制小屋，查看事件连接状态。
2. 在本机 Codex 聊天中发送“执行一下 `pwd`”，让它完成一次工具调用和回复。
3. 检查控制小屋是否变成 **“已收到事件”**，且“最近事件”显示刚才的时间。通常会依次出现思考、敲代码、回复结束吃饭；短暂状态可能一闪而过。

**“提醒桥已就绪”只表示桌宠已经准备好接收消息，不代表 Hooks 已安装、已信任或真实联动成功。** 手动演示和动作连播也不能证明真实接入成功。

### 常见问题与撤销

| 现象 | 检查方法 |
|---|---|
| 一直显示“等待首次事件” | 确认配置已安装到 Codex 使用的目录、对应 Hooks 已信任且启用，再发送新消息；若配置未刷新，结束当前运行后重启 Codex 再试。 |
| 设置中找不到 Hooks | 确认所用 Codex 版本支持 Hooks；命令行版使用交互式 `/hooks` 入口。 |
| 显示“提醒桥不可用” | 查看面板给出的具体错误；如设置了 `WHALE_DATA_DIR`，桌宠和发送脚本必须指向同一目录。 |
| 动画联动了，但没有系统通知或声音 | 检查小屋的通知、提示音开关，以及 macOS 通知权限和专注模式。提示音默认关闭，普通思考和工作状态不会发送系统通知。 |
| 移动项目目录或更换 Node 路径后失效 | 配置记录的是绝对路径。移除指向旧位置的本项目 Hook 条目，再从新位置重新安装并审核；保留其他项目的 Hooks。 |

撤销时，只移除配置中命令指向本项目 `scripts/codex-hook.cjs` 的条目，保留其他配置；也可以在 Codex 的 Hooks 管理界面禁用这些条目。

### 已接入的事件

| 事件 | 表现 |
|---|---|
| UserPromptSubmit | 思考中 |
| PreToolUse | 敲代码 |
| PermissionRequest | 权限检查，提示可能需要确认；不保证确认框真的在等待 |
| PostToolUse | 匹配工具返回，清除对应权限检查；其他调用仍运行则继续工作，否则回到思考 |
| Stop | 按聊天保存本轮结束的未读提醒，显示标题、剩余活动聊天数，可选系统通知与提示音 |
| Interrupt / SessionEnd | 该会话回到空闲 |

“本轮回复结束”不意味着测试通过或整个任务成功。重复 Stop 去重；多个聊天同时活动时，权限检查优先于工作中。没有后续事件的异常退出暂不自动推断为完成。

### 权限检查状态恢复

`PostToolUse` 接入后，工具返回（包括命令非零退出）会清除匹配的权限检查，不增加完成提醒或成长。按聊天、轮次、调用 ID 跟踪，其他工具或其他聊天返回不能清除仍在进行的检查；结束或中断后的迟到事件会忽略。

`PermissionRequest` 只代表进入审批流程，自动批准也可能经过此流程，所以界面显示“权限检查”，不把它直接称为“等待你批准”。此事件未保证提供调用 ID；同名工具并行且无法唯一匹配时，保守等候候选调用返回或该轮结束。长命令尚未返回期间，单靠这组 Hooks 不能知道确认框何时关闭，不会用时间超时猜测批准结果。

桌面 Codex 额外使用只读状态观察器：连接当前用户已有的 `$CODEX_HOME/ipc/ipc.sock`，仅订阅由 Hooks 登记且仍活动的本机正式聊天。先按聊天、轮次、工具调用 ID 绑定实际审批请求，再观察“请求已清空且退出等待”，移出匹配的待处理；仍活动则回到执行中，已空闲则清理实时状态，不等待长命令返回，不新增完成提醒、成长、通知或 Hook 计数。一个聊天仍有其他请求时继续保留待处理，旧请求的结束不会清除同轮刚到达的新申请。

观察器不启动或接管 Codex 服务，也不发送批准、拒绝、对话或配置修改。客户端 IPC 快照可能携带历史内容，解析后立即丢弃，只在内存保留轮次、请求及调用 ID 和运行状态，不保存快照或正文。当前适配桌面 IPC 的 `thread-stream-state-changed` 第 11 版协议；它不是稳定的公共 API，断线、版本或补丁链不匹配会重连并清除观察凭据，期间退回原有 Hooks。未观察到对应请求或无法匹配调用时保守等待工具返回，不凭普通工作状态或时间超时猜测授权。关闭 Codex 来源接收后停止订阅。CLI 或未提供兼容 IPC 的客户端仍使用 Hooks。

可运行 `npm run test:approvals` 验证隔离 Electron 下的审批同步、并行聊天、重连和接收开关。

已安装旧版的用户运行 `node scripts/hooks/install.cjs --install` 补充 `PostToolUse` 后，在 Codex 设置 → Hooks 中审核并信任新增条目。已有六项定义保持不变，不需要重新信任未变化的条目。Hooks 提醒和只读观察器不批准或拒绝操作；微信网关只回传用户对网关自身任务的明确审批。

### 多聊天与未读提醒

- 同时进行三个聊天，其中一个回复结束时，人物头顶气泡显示蓝色“已完成：1”和暖棕色“执行中：2”，两个入口分别有对应的悬停颜色；执行中为 0 时隐藏该入口。三类提醒共用“快捷操作”中的合并阈值（默认 3），各类分别计数；阈值内直接展示，超过阈值默认折叠，点击数量可展开或收起。默认分类依次选择有内容的待处理、已完成、执行中，也可点击入口切换。执行中同样支持单个直达、多个在原气泡选择，打开执行中聊天不改变其工作状态或完成提醒。未处理时常驻；普通台词出现时蓝色气泡向上让位，普通台词颜色不变。
- 单条提醒跳转失败时保留提醒并打开小屋显示错误；气泡内跳转失败则在原气泡显示重试提示。也可通过小屋的“聊天与提醒”查看全部记录。
- 完成提醒在合并阈值内（默认 1～3 条）直接显示任务名称；只有一条时，点击名称或完成数量均直达对应对话；超过配置阈值时点击完成数量，才在桌宠原气泡内展开聊天名称，保留数量入口，不额外显示提示标题，点击任意一行打开对应对话，只清除该条。气泡最多显示四行，更多条目可滚动；鼠标悬停和键盘聚焦高亮，相邻行使用交替底色增强反馈，方向键选择、Esc/点击外部收起，收起不清除提醒。小屋中每条提醒仍可单独“标为已读”，或点“打开聊天”跳回对应 Codex 聊天并将该条标为已读。只打开列表不会清空提醒；同一聊天只保留最新一条提醒，“任务完成”数量按有未读完成回复的聊天数统计，不按回复轮次累加；它表示本轮回复结束，不保证整个任务成功。
- 只统计本地 Codex 正式聊天，排除未登记临时会话和子代理。桌宠只读同步 `.codex-global-state.json` 的本机已读状态；聊天被看过或继续回复后移除旧提醒。结束事件后留出 3 秒同步时间，陈旧、不可读或未知版本的侧栏状态不会清除提醒，可在小屋手动处理。
- 系统通知也带聊天标题和剩余活动数，点击打开对应聊天。跳转使用官方 [聊天深链接](https://learn.chatgpt.com/docs/reference/commands#deep-links)。系统是否展示横幅取决于 macOS 的通知权限。
- 未读和轮次去重记录保存在数据目录的 `reminders.json`，最多保留 100 个聊天的待查看提醒。重启会恢复未读，不恢复上次进程的“进行中”状态；列表只统计桌宠启动后收到事件的聊天，未收到结束事件的异常退出不猜测为完成。
- 名称优先使用 Codex 侧栏的 `name` 字段，缺失时回退 `title`。仅通过只读 SQLite 查询 `$CODEX_HOME/state_5.sqlite`（默认 `~/.codex/state_5.sqlite`）中事件对应的聊天 ID；不读取聊天正文或凭据。该文件是 Codex 内部存储，缺失、版本变化或查不到标题时显示“聊天 + 短 ID”。标题和结束事件元数据仅保存在本机。
- 审批提醒优先于完成动画；蓝色提醒仍保留。透明窗口顶部预留双气泡空间，气泡靠近人物，不显示名称栏。底部按钮只在鼠标经过人物或按钮时显示，透明留白不触发；键盘聚焦时也可操作。全部处理后蓝色气泡自动消失。

官方依据：[Hooks 文档](https://learn.chatgpt.com/docs/hooks)。本地 Hooks 不适用于云端编排任务。目前报错、提问是手动演示动作，事件桥尚未接入相应真实信号；不会用普通工具调用猜测报错或用户提问。

## Hooks 来源配置

小屋左栏的“Hooks 配置”提供 Codex 和 Cursor 的独立接收开关、最近接收状态、内置事件对应表与可复制的接入配置。开关立即生效并保存到桌宠的 settings.json；Cursor 启动时以实际配置和保存的接收偏好共同决定开关状态，无配置时关闭。

- 暂停来源后，新事件不触发动作、任务计数、成长或通知；清除该来源当前活动状态，保留已有完成提醒。重新启用后从新事件接收，不补历史或重放完成动画。
- Codex 接收开关不修改客户端配置或信任；Cursor 总开关开启时创建或补齐全部 5 项，修改前备份并保留其他配置。逐项开关仅控制桌宠接收，不增删 JSON。关闭总开关仅暂停桌宠接收，不删除文件或事件。
- Codex 沿用已安装的发送端和本机聊天名称、跳转、已读同步。Cursor 使用独立发送端和会话命名空间，只读本机 Cursor 的 composerHeaders 聊天标题与子代理标记，显示“Cursor · 标题”，读取不到时回退短 ID；不提取提示词、聊天正文、工具输入输出、账号或 transcript 文件。审查等派生子代理不单独计入执行中或完成提醒；标记晚于 Hook 到达时，后续同步自动清理残留，无需等待子代理结束事件。无法读取元数据时保留普通聊天，不按标题或超时猜测结束。
- Cursor 通过智能体深链接打开对应对话；只有点击提醒并确认跳转成功、手动标为已读，或继续给该对话发送消息时，才清除对应完成提醒。后台保存的“上次选中对话”不能证明用户看过新结果，不用于自动清除。当前没有可靠的 Cursor 原生已读同步，直接在 Cursor 中查看而未发送新消息时，提醒会保留，可在小屋手动标为已读。跳转失败及其他对话的提醒保留，Codex 的已读同步不会清除 Cursor 提醒。

Cursor 配置也可生成预览：`node scripts/hooks/cursor-config.cjs`，或在配置页展开“查看接入配置”。当前内置 beforeSubmitPrompt、postToolUse、postToolUseFailure、stop、sessionEnd；stop 仅 completed 记完成，aborted/error 记停止。用户已通过真实 Cursor 事件验证接收联动。第一版不接入工具权限拦截 Hook，不伪造权限检查事件。

映射依据：[Cursor Hooks](https://cursor.com/docs/hooks)。接收与 UI 已用隔离的真实本地 socket/Electron 验证。

子代理回归：`node --test test/chat-metadata.test.cjs test/activity.test.cjs test/client-presence.test.cjs test/hook-adapters.test.cjs`；`WHALE_CURSOR_SUBAGENTS_ONLY=1 PLAYWRIGHT_MODULE=/path/to/playwright node scripts/checks/client-presence-smoke.cjs` 使用临时数据库和隐藏窗口，检查标记延迟时的气泡、动画清理及普通聊天保留，不重放完成通知或成长。

### 自动检测接入状态

小屋启动及点击“重新检测”时只读检测客户端配置；开启来源时检测可用状态。Cursor 未检测到鲸鱼娘配置时，启动总开关默认关闭，旧版保存的开启状态也不会覆盖此判断。主动开启时补齐全部 5 项配置；首次创建默认接收全部，已有配置保留逐项接收偏好。Codex 通过本机 app-server 的 hooks/list、config/read 和 configRequirements/read 检查鲸鱼娘命令的启用、信任及全局 Hooks 开关；不匹配其他插件的同名事件。未接入、未信任、已禁用或状态未知的事件置灰，不触发陪伴效果。检测基于本项目所在工作区的配置上下文，不代表其他项目、远程环境或正在运行的旧会话。

Cursor 读取用户级 hooks.json，仅确认本项目命令是否已配置，实际生效需收到真实事件验证。开启总开关时，文件不存在则创建全部 5 项，已有文件则补齐缺失的本项目命令；保留其他插件、事件和配置字段，修改前生成同目录备份。逐项接收开关不修改 JSON。启动读取实际配置，缺失项置灰；已配置项结合保存的接收偏好显示状态。JSON 异常或写入失败不会覆盖文件，开关回退。启动及重新检测均不写配置，Codex 配置和信任始终只读。移动目录、更换 Node 或更改配置后，请重新检测。


### 客户端退出与提醒恢复

桌宠每 3 秒定时只读检测本机 Cursor、Codex 桌面主进程（当前 ChatGPT 桌面宿主也视为 Codex），启动、接收 Hook 和跳转前也会即时检测。真正退出时，该来源的任务暂时隐藏，不计入待处理、已完成和执行中数量；完成记录仍保存在 reminders.json。重新打开后恢复未确认完成记录的原有顺序，不重新发送通知或累计成长。最小化、切换或关闭窗口但主程序仍运行，不隐藏提醒。执行中与待处理状态在退出时清理，重开后等待新的有效 Hook。

跳转前会重新检测客户端；已退出或检测失败时不发送系统跳转链接，保留记录并提示。进程检测失败不当作退出，保留上次有效显示状态。Codex 已读同步不消耗已退出时暂存的完成记录。

隔离验证：`PLAYWRIGHT_MODULE=/absolute/path/to/playwright node scripts/checks/client-presence-smoke.cjs`。测试只模拟进程清单，不退出用户真实客户端。
